# Skill: release-pyc (Universal)

Build a `cp311-cp311-win_amd64` wheel where `application/` and `infrastructure/`
`.py` source files are compiled to `.pyc` bytecode and removed, protecting IP
while preserving IDE type hints through `.pyi` stub files.

The build uses `setup.py` with custom `BuildPyWithPyc` + `BdistWheelCp311` hooks
that operate on the build directory -- **source files are never modified**.

This skill works for any instrument driver project that follows the standard
protection pattern. For project-specific details (exact file lists, error messages),
refer to the per-project skill at `.claude/skills/release-pyc/skill.md` inside
the target project directory.

---

## Auto-Detection

Before running, determine which project is being targeted:

1. **Package name** -- read from `pyproject.toml` under `[project] name`
2. **Build script** -- check if `scripts/build_pyc_wheel.bat` exists
3. **setup.py** -- check it contains `BuildPyWithPyc` and `BdistWheelCp311`

If the project does not have `scripts/build_pyc_wheel.bat`, stop and report that
the project has not been set up for pyc wheel builds.

---

## Standard Protection Pattern

All instrument driver packages protect the same two layers:

| Layer | Action |
|---|---|
| `application/` | Compiled to `.pyc`, `.py` removed, `.pyi` generated by stubgen |
| `infrastructure/` | Compiled to `.pyc`, `.py` removed, `.pyi` generated by stubgen |
| `domain/` | Kept as `.py` -- public abstract interfaces |
| `shared/` | Public utility types kept as `.py`; some packages also compile shared helpers |
| `__init__.py` | Always kept as `.py` in every directory |

Some packages preserve additional files as `.py` (e.g., `Virtual_Scope.py` in
`scope_driver`). These are listed in the project's `KEEP_FILES` set inside `setup.py`.

---

## Pre-flight Check

Before running the build, verify all of the following:

1. `.venv\Scripts\python.exe` exists
   - If missing: `call template_project\scripts\create_venv.bat -local -dev`
2. `setup.py` exists at project root and contains `BuildPyWithPyc` and `BdistWheelCp311`
3. `pyproject.toml` contains `application/__pycache__/*.pyc` and `infrastructure/__pycache__/*.pyc`
   in `[tool.setuptools.package-data]`
4. `scripts/build_pyc_wheel.bat` exists

If any check fails, report the specific issue and stop.

---

## Run the Build

Execute from the project root:
```
call scripts\build_pyc_wheel.bat
```

Watch the output for:
- `[ERROR]` lines -- fatal, stop and diagnose
- `[WARNING]` lines -- note but continue (usually stubgen import resolution issues)
- `Build SUCCESS:` line -- confirms the wheel path

---

## Verify Results

After a successful build, confirm the wheel contains the expected files.
The exact file list depends on the project -- check the per-project skill for
the full list. In general:

**Must have `.pyc`** (in `__pycache__/` subdirectory with `cpython-311` naming):
- All `application/` implementation modules
- All `infrastructure/` hardware driver modules

**Must have `.pyi`** (in the layer directory alongside `__init__.py`):
- One `.pyi` per compiled module (generated by stubgen or checked in)

**Must NOT have bare `.py`** in protected dirs (except `__init__.py` and any
files listed in `KEEP_FILES` within `setup.py`):
- All `Standard_*.py` and driver `.py` files should be absent from protected dirs

Quick verification command (replace `PACKAGE` and `VERSION`):
```
.venv\Scripts\python.exe -m zipfile -l dist\PACKAGE-VERSION-cp311-cp311-win_amd64.whl
```

## Error Diagnosis

| Error | Cause | Fix |
|---|---|---|
| `Virtual environment not found` | `.venv` missing | `call template_project\scripts\create_venv.bat -local -dev` |
| `setup.py not found` | setup.py missing | Verify `setup.py` exists at project root |
| `Failed to install wheel` | pip/network issue | `.venv\Scripts\pip install wheel` manually |
| `Failed to install mypy` | pip/network issue | `.venv\Scripts\pip install mypy` manually |
| `No .pyc files found in wheel` | Missing globs in package-data | Add `application/__pycache__/*.pyc` etc. to `pyproject.toml` |
| `Unexpected .py files in protected dir` | `KEEP_FILES` mismatch in setup.py | Update `KEEP_FILES` or `PROTECTED_SUBDIRS` in `setup.py` |
| stubgen warnings | Import resolution failure | Non-fatal; install `am_shared` and `visa_bundle` in venv to resolve |

## Notes

- `setup.py` NEVER modifies source files -- only operates on the build directory
- All `__init__.py` files are always preserved as `.py`
- This wheel is **Python 3.11 only** (`cp311-cp311-win_amd64`) -- will not install on 3.10 or 3.12
- Running the build again is safe and idempotent
- The `py3-none-any.whl` from `python -m build --wheel` is a different (unprotected) build
- `py.typed` (PEP 561 marker) is included via package-data so type checkers recognize the package
